# Security policy

## Supported versions

Symbols has not made its first release. No released version currently receives
security updates. Until a release is published, fixes are made on the default
development branch and may include breaking changes.

After releases begin, this section will list the supported release lines and
their security-update status.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
pull request, or chat.

Use **Security → Report a vulnerability** on this repository to open a private
security advisory. Include, when possible:

- affected revision, artifact, and platform;
- a concise description of the impact and threat model;
- reproduction steps or a minimal proof of concept;
- whether the issue is already public or has been reported elsewhere; and
- any suggested mitigation.

If private vulnerability reporting is unavailable, open a public issue that
asks the maintainers to establish a private contact channel. Do not include
vulnerability details in that issue.

Maintainers will acknowledge reports and coordinate validation, remediation,
release, and disclosure on a best-effort basis. Response or fix timelines
cannot be guaranteed. Please allow a reasonable remediation period before
public disclosure, while recognizing that immediate disclosure may be
appropriate when active exploitation or user safety requires it.

## Scope

Security reports may cover project source code, published artifacts, build and
release automation, generators, parsers, font/resource handling, and the
project's dependency or supply chain. General support questions, feature
requests, and bugs without a security impact belong in the public issue
tracker.
